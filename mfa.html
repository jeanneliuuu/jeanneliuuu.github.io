Overview

Building the entire MFA experience from zero

Introducing MFA meant rethinking how users access and secure their accounts across the product. Because authentication touches the entire product, the experience needed to work across enrollment, sign-in, recovery, account settings, and security communications, not just the MFA flow.

The goal was to establish a cohesive authentication experience that strengthened account security without adding unnecessary friction.

Challenge

Security that doesn't feel like a wall

MFA introduced a critical product challenge: improving security without creating unnecessary friction and strengthening account security without disrupting the workflows users already relied on. 

1
Authentication introduced new user states
Verified, unverified, locked, and recovery states didn't exist in the product yet. Each required clear behaviors, messaging, and transitions.
2
Authentication spanned multiple entry points
Login, password reset, device changes, and account settings all needed to feed into a consistent authentication experience.
3
Recovery needed to account for multiple scenarios
Users could lose access because of a forgotten password, lost device, or failed verification. Each scenario needed a clear recovery path that allowed users to regain access without relying on support.
Research

Mapping the authentication landscape

Before designing a single screen, I mapped where users could enter, leave, or regain access to an authenticated session, from login and deep links to password resets, session expiry, and device changes. I then benchmarked established authentication experiences to compare enrollment, verification, recovery, and security messaging across different products. The research resulted in a shared state model that became the reference point for the authentication experience.

Design approach

Defining the authentication experience

01

Enrollment as a guided setup

Enrollment uses an authenticator app as the sole method at launch, with setup, verification, and backup codes organized into three focused steps with visible progress, rather than a settings toggle buried in account preferences.

02

Notifications as the safety net

Every security-relevant event (new device sign-in, failed attempts, recovery started) triggers both an in-product and email notification, so a user always has a record and a way to act even if they weren't the one who triggered it.

03

Recovery without a dead end

Failed verification and lost devices route into a self-serve recovery flow using backup codes or a secondary contact method, so users aren't stuck waiting on support to regain access.

Final Designs

Enrollment

A guided setup: choosing a verification method, confirming it works, then saving backup codes before enrollment is complete.

Verification

Every login checks device trust first; unrecognized devices trigger a code challenge and a parallel alert so the account owner always knows.

Recovery

A self-serve path back in for a lost device or failed attempt, using a saved backup code or secondary contact — no support ticket required.

Login recovery · Error states

Errors explain what happened, preserve the user's progress, and provide a clear next step. The experience adapts to the severity of the error, from correcting a mistyped code to moving a locked-out user into recovery.

Wrong authenticator code

Keeps entered digits visible and returns focus to the first field. Attempt limits appear only when relevant.

Backup code already used

Clearly distinguishes an expired code from a mistyped one and shows how many codes remain.

Last attempt before lockout

Attempt limits appear only when users have two tries left, escalating at one remaining with a clear warning.

Out of attempts

Removes the inactive input and replaces it with a clear next step and countdown. Admin recovery remains available.

Session expired mid-recovery

Treats expiration as a system event rather than a user error. Users return to the previous step instead of starting over.

Reset request already pending

Shows the active request instead of allowing a duplicate submission, keeping both the user and admin workflow clear.

Responsive across web and mobile

Every step of the experience uses one responsive layout rather than a separate mobile flow. Enrollment, code entry, backup codes, and recovery reflow to a single column on small screens, with inputs and controls sized for touch so a user can enroll on desktop and verify on their phone without relearning the flow.

Takeaways

Learnings

1

Start with the system, not the screen

I learned that for complex product problems, mapping the states, dependencies, and entry points early creates a stronger foundation for the decisions that follow.

2

Security and usability need to be designed together

Security can easily introduce friction when treated as a separate layer. Designing recovery, error states, and notifications alongside the core authentication flow helped create an experience that could protect the account without leaving users confused or stranded.
